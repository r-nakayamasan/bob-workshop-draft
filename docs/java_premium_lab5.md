## 1. はじめに

### 依存ライブラリの脆弱性検出とは

すべての Java アプリケーションは、直接的（`pom.xml` に宣言）または間接的（他のライブラリ経由で取り込まれる推移的依存関係）にサードパーティライブラリに依存しています。これらのライブラリはいずれも、CVE として公開された既知のセキュリティ脆弱性を持つ可能性があります。

依存ライブラリの脆弱性検出は以下のプロセスです。

- **スキャン**: 直接・推移的なすべての依存関係を確認
- **照合**: 公開された CVE データベースと照合
- **報告**: 各一致について深刻度・影響バージョン・修正推奨事項を報告
- **修正**: 脆弱性のある依存関係をアップグレードまたは除外

### このラボについて

**Bob V2 の Java Vulnerabilities Detection ワークフロー**を使って、薬局アプリケーションの依存関係をスキャンし、各検出結果を理解して、脆弱性のあるライブラリをアップグレードして修正します。

| 項目 | 内容 |
|------|------|
| **修正前** | `pom.xml` に脆弱性のある依存関係バージョンが含まれる薬局アプリ |
| **修正後** | 脆弱性のある依存関係をアップグレード済み、クリーンなスキャン結果、修正の記録が残された同アプリ |

### 学習目標

このラボを完了すると、次のことができるようになります。

- Java Vulnerabilities Detection ワークフローを起動してスキャン出力を解釈できる
- 直接依存関係と推移的依存関係の脆弱性の違いを理解できる
- Bob のインタラクティブな修正フローを通じて依存関係のアップグレードを承認できる
- 修正後もアプリがクリーンにビルドできることを確認できる

## 3. V2 の注目機能

このラボで注目すべき Bob V2 の機能です。

| 機能 | 説明 |
|------|------|
| **トップレベルのスタンドアロンワークフロー** | Java Vulnerabilities Detection は専用のトップレベルワークフロー（Java Modernization のサブタイプではない） |
| **高速・決定論的なスキャン** | モダナイゼーションワークフロー（反復的・自律的）とは異なり、このスキャンは数秒で完了 |
| **直接 + 推移的な依存関係のスコープ** | Bob が完全な依存関係ツリーを解決し、`pom.xml` に直接宣言されたものだけでなく推移的な脆弱性も報告 |
| **インタラクティブな修正フロー** | 検出された各 CVE に対して、Bob が具体的な修正案（通常はバージョンアップ）を提案して承認を求める |
| **タスクごとのコスト内訳** | 短いワークフロー実行でもタスクごとのコストとトークン数を表示 |

## 5. 演習 1：Vulnerabilities Detection ワークフローを実行する

### 目的

ワークフローをトリガーして、Bob に完全な依存関係スキャンを実行させます。

### 手順

#### ステップ 1：ワークフローを開始する

Bob のチャットパネルで **Java Vulnerabilities Detection** ワークフローの **Start** をクリックします。

#### ステップ 2：依存関係の検出

Bob が `pom.xml` を読んで完全な依存関係ツリー（直接 + 推移的）を解決し、スキャンするパッケージの数を報告します。

#### ステップ 3：CVE の照合

Bob が各検出パッケージの CVE データベースを照合します。このプロジェクトのサイズでは通常 30 秒以内で完了します。

#### ステップ 4：検出結果レポート

Bob が検出された各脆弱性を以下の情報とともに報告します。

| 項目 | 内容 |
|------|------|
| 影響を受けるパッケージとバージョン | |
| CVE 識別子 | |
| 深刻度 | Critical、High、Medium、Low |
| 依存関係の種別 | 直接依存か推移的依存か |
| 修正の推奨事項 | |

## 6. 演習 2：CVE の検出結果を確認する

### 目的

Bob が見つけた内容を理解し、修正前に優先順位を付けます。

### 手順

#### ステップ 1：各検出結果を読む

各 CVE について以下を確認します。

- 脆弱性のあるライブラリは直接宣言されているか、推移的に取り込まれているか？
- Bob が推奨する修正バージョンは何か？
- 深刻度はどうか、またそのアプリでの実際の使用方法に適用されるか？

#### ステップ 2：検出結果をグループ化する

以下の観点で整理します。

- 素早く修正できるもの（単純なバージョンアップ）はどれか？
- 推移的依存関係の除外と直接置換の追加が必要なものはどれか？
- 同じ脆弱性バージョンを複数のパスで取り込んでいる重複はあるか？

#### ステップ 3：各 CVE を理解してから修正する

馴染みのない CVE については、Bob に直接質問しましょう。

```
CVE-XXXX-XXXX について平易な言葉で説明してください。このアプリケーションにどのような影響があるか教えてください。
```

Bob がその脆弱性の概要と実際への影響を説明します。

## 7. 演習 3：検出された脆弱性を修正する

### 目的

インタラクティブな修正フローを通じて Bob が提案した修正を適用します。

### 手順

#### ステップ 1：修正を開始する

検出結果レポートから Bob に修正を進めるよう伝えます。Bob が CVE を 1 件ずつ処理します。

#### ステップ 2：インタラクティブな承認フロー

各検出結果に対して Bob は以下を行います。

1. CVE とその影響を説明する
2. 具体的な `pom.xml` の変更（バージョンアップ、除外 + 直接依存関係、`<dependencyManagement>` ピンなど）を提案する
3. 適用前に承認を求める

#### ステップ 3：個別の変更内容をプレビューする

提案内容が不明な場合は、正確な `pom.xml` の変更を確認するオプションを選択してください。Bob が適用前に diff をレンダリングします。

#### ステップ 4：順に承認する

Bob が提示した順序で各 CVE を処理します。Bob が各変更を適用してから次に進みます。

#### ステップ 5：連鎖的な影響に対処する

修正によって二次的な問題が発生することがあります（例：新しいメジャーバージョンへのアップグレードが他の箇所の API 変更を必要とする）。Bob がこれらを特定して追加修正の承認を求めます。

## 8. 演習 4：修正後のアプリケーションを確認する

### 目的

アプリがまだビルドできることを確認し、再スキャンで CVE がクリアされていることを確認します。

### 手順

#### ステップ 1：コンパイル確認

Bob のターミナルで:

```bash
mvn clean compile
# BUILD SUCCESS が表示されることを確認
```

#### ステップ 2：ワークフローを再実行する

**Java Vulnerabilities Detection** ワークフローの **Start** を再度クリックします。Bob が検出結果ゼロまたは大幅に減少したリストを報告するはずです。

#### ステップ 3（オプション）：Liberty サーバーを起動する

```bash
mvn liberty:run
```

アップグレードによるランタイムエラーなしに API が起動することを確認します。

```
http://localhost:9081/simple-pharmacy/api/dashboard
```

## 9. トラブルシューティング

### ワークフローが脆弱性ゼロと報告する

**症状**: Bob のスキャンが「検出されたパッケージに影響する脆弱性は見つかりませんでした」で完了する

**対処法**: これは正当な結果（クリーンな依存関係）の可能性もありますが、このラボでは `pom.xml` にラボが想定する意図的に脆弱なバージョンが含まれていないことを意味します。`snapE-*` の開始スナップショットを開いていること、かつ変更していないことを確認してください。

---

### バージョンアップ後に `mvn compile` が失敗する

**症状**: CVE の修正でライブラリが破壊的な API 変更を含むバージョンにアップグレードされ、コードがコンパイルできなくなる

**対処法**: コンパイルエラーを Bob に貼り付けて API の変更に対応するよう依頼します。Bob がコードを修正するか、（まだセキュアな）別のバージョンを提案します。

---

### 推移的依存関係がクリーンにアップグレードできない

**症状**: CVE が推移的依存関係内にあり、別のライブラリが古いバージョンを必要としているためシンプルなバージョンアップができない

**対処法**: Bob は通常、外部依存関係への `<exclusions>` ブロックと修正済みバージョンの直接宣言を提案します。プロンプトが表示されたら承認してください。

---

### Bob のターミナルで Java バージョンが異なる

**症状**: Bob のターミナルで `java -version` が 21 以外のバージョンを表示する

**対処法**: Bob のターミナルで以下を実行します。

```bash
sdk use java 21.0.11-zulu
```

`sdk use` はシェルスコープのため、ターミナルタブには適用されません。
